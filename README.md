# 每日打卡 · DailyCheck

一个面向**长期备考 / 长期目标**的 Windows 桌面打卡工具。

四层目标层层拆解，每日任务自动汇总成「今日必做」，进度按真实坚持天数计算 —— 打开就知道今天该干什么。

## 它解决什么问题

市面上的打卡 App 大多只做「今天打没打勾」，但备考这类长期目标需要的是：

- **层层拆解** —— 总目标 → 本月 → 本周 → 今天，想分多细就分多细，层级不限
- **真实进度** —— 漏打卡的日子要算进分母，进度条不能骗自己
- **每天聚焦** —— 长期任务（「背 50 个单词」）自动出现在今日清单，不用天天翻目标

DailyCheck 按这三点设计。

## 核心特性

| 特性 | 说明 |
|---|---|
| **四层目标** | 总目标 → 本月 → 本周 → 今天，支持无限层级子目标，进度自下而上汇总 |
| **两种任务** | 一次性任务（做完打勾即结束）与每日任务（每天重置，第二天自动变回未打勾） |
| **今日必做** | 所有上层目标里的每日任务自动汇总到一处，每天集中打卡一次即可 |
| **真实进度算法** | 每日任务的「没打卡的天」计入分母，完成率反映真实坚持情况 |
| **倒数日** | 置顶显示考试 / 截止日期剩余天数，支持每年重复 |
| **AI 复盘** | 一键导出数据快照，或直接调用本机 `claude` 命令行做分析并给出下周目标 |
| **断电保护** | 写入前先落临时文件再替换；数据损坏时自动备份为 `.bad` 而非直接丢失 |
| **跨天自动切换** | 程序常驻也不怕，每分钟检查日期，跨天自动切换到新的一天 |
| **单实例保护** | 防止两个窗口同时改数据互相覆盖 |
| **开机自启** | 一个勾选框搞定，路径变了会自动重写注册表 |

## 快速开始

### 方式一：直接下载（推荐）

到 [Releases](https://github.com/MuZiLi6667/DailyCheck/releases) 下载 `DailyCheck.exe`。

**免安装单文件版**，运行时已打包进去，双击即用，无需安装 .NET。

### 方式二：从源码构建

需要 [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0)。

```bash
git clone https://github.com/MuZiLi6667/DailyCheck.git
cd DailyCheck

# 本机版（体积小，需目标机器装有 .NET 9 运行时）
dotnet publish DailyCheck/DailyCheck.csproj -c Release -o app

# 免安装单文件版（约 57 MB，双击即用）
dotnet publish DailyCheck/DailyCheck.csproj -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true -o app-portable
```

也可以直接用 VS2022 打开 `DailyCheck.sln`（需勾选「.NET 桌面开发」工作负载）。

## 两种任务，一张表看懂

每个目标下都能点「＋ 任务」或「＋ 每日」：

| 按钮 | 类型 | 行为 |
|---|---|---|
| **＋ 任务** | 一次性 | 做完打勾就结束。比如「看完第 3 章」 |
| **＋ 每日** | 每日 | 每天都要做，第二天自动变回未打勾。比如「背 50 个单词」 |

每日任务会自动出现在「今日必做」区，不用重复添加；不用了就在原处删掉。

## 进度怎么算

**每日任务的「没打卡的天」会算作未完成**，这就是天数起作用的地方：

```
本周目标下有「跑步 3 公里」这个每日任务
本周一建立，今天周六 → 中间过了 6 天
实际只跑了 2 天

→ 跑步这项 = 2/6，不是 2/2
→ 本周进度 = (3.1节 1/1 + 3.2节 0/1 + 跑步 2/6) = 3/8 = 37.5%
```

各层统计区间：

| 层级 | 统计区间 |
|---|---|
| 总目标 | 从第一次使用那天 → 今天 |
| 本月 | 本月 1 号 → 今天 |
| 本周 | 本周一 → 今天 |
| 今天 | 只看今天 |

一次性任务不参与天数计算（做完就是 1/1）。

> 每日任务的统计起点是它被创建的那天，不会把创建之前的日子算成「没打卡」。

## AI 复盘

程序每次启动都会把最新数据写成快照：`data/ai-snapshot.md`。

**用法一 · 交给 Claude Code（推荐）**

在 Claude Code 里直接说：

> 读一下 `data/ai-snapshot.md`，分析我的打卡情况，再帮我制定下周目标

不光能分析，还能让 Claude **直接帮你把目标和任务写进程序**。

**用法二 · 程序内一键分析**

点界面上的「AI 分析」按钮，会调用本机已安装的 `claude` 命令行做无头分析（消耗额度，约 30~90 秒），结果会存成 `data/ai-advice.md`。

> 需要本机已安装 Claude Code CLI 并完成登录。

## 数据存储

所有数据存在一个纯文本 JSON 文件里：

```
<程序所在目录>/data/dailycheck.json
```

- 点界面上的「数据目录」按钮可直接打开该文件夹
- 随时可以备份，或拷到别的电脑继续用
- 想清空重来？删掉这个文件即可

**换电脑携带记录：** 在新电脑上先运行一次程序生成 `data` 目录，再把旧机器的 `dailycheck.json` 覆盖过去，重开程序即可。

## 常见问题

**Q：双击图标提示「已经在运行了」？**
程序只允许开一个窗口，防止两个窗口同时改数据互相覆盖。去任务栏找找。

**Q：文件夹搬走了，开机自启还有效吗？**
重新运行一次程序，会自动把注册表指向新路径。

**Q：一直开着不关，第二天会怎样？**
程序每分钟检查一次日期，跨天自动切到新的一天，昨天打勾的记录会存档。

**Q：每日任务漏打卡几天，进度掉得厉害？**
这是故意的 —— 进度要反映真实坚持情况。如果某个每日任务不想继续了，直接删掉，历史统计会一并移除。

**Q：数据文件损坏了怎么办？**
程序会先把原文件备份成 `dailycheck.json.bad`，再以空数据启动，不会静默丢失。
